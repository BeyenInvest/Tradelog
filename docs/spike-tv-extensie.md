## Wat het owner-rapport moet laten zien

1. **Probe-JSON**: `symbol`, `resolution`, `symbolExt` (met `pricescale`/`minmov` → tick-size, C8), en in `shapes.list` een entry met een position-achtige `name` waarvan `points`/`properties` entry/SL/TP-prijzen bevatten. Let op: bij TV's risk/reward-tool kunnen SL/TP als **`stopLevel`/`profitLevel` in ticks** in `properties` zitten i.p.v. als losse points — beide vormen zijn bruikbaar voor F2a, maar bepalen de adapter-vorm.
2. **Snapshot**: preview toont alleen de chart (geen watchlist/accountnaam), `bytes` < 5 MB.
3. **Log**: ≥ 2 `alarm-refresh`-regels met `ok: true` en **verschillende** `bootAt` → sessie + refresh overleven SW-restarts.
4. **verifyOtp**: `ok: true` + daarna een geslaagde `test-db` (RLS-read op `profiles`).

## EINDCONCLUSIE (2026-09-16): alle vier punten GO — runtime bewezen in echte Chrome

De spike is afgerond in één sessie (owner voerde de runtime-tests uit, Fable verifieerde). **F1 kan exact volgens plan §2.2 gebouwd worden.** Bevindingen die de bouw vormgeven:

1. **F2a-adapter:** het probe-rapport (deze sessie, chart `MshnPeEI`, OANDA:AUDJPY 240) is de eerste contract-fixture. Position-tool-vorm: `points[0]` = entry-prijs + bar-time; SL/TP = `properties.stopLevel/profitLevel` **in ticks t.o.v. entry**; tick = `_minMove / _priceScale` uit `priceFormatter()` (underscore-props → defensief lezen, fallback: decimalen tellen in `format()`-output). Ook gratis mee: `accountSize`, `risk`, `qty`, `symbolExt` (type "forex" → symbol-normalisatie M5).
2. **F3a-snapshots:** `captureVisibleTab` vereist een **activeTab-gebaar** (action-klik) per tab — host-permission volstaat niet. Ontwerp-opties: één verplichte action-klik per sessie, óf TV's eigen `takeClientScreenshot`/`takeScreenshot` (op de API ontdekt) als primaire route — in F3a eerst proben. Crop-selector `.chart-container.active` werkt; 95 KB/PNG betekent dat 4 slots per trade ~0,4 MB kosten (bucket-groei valt mee, plan-risico 7 kleiner).
3. **Auth (F1a/F1b):** `generateLink` (secret-key server-side) → `verifyOtp(token_hash, 'magiclink')` → sessie in `chrome.storage.local`, refresh op `chrome.alarms` met `autoRefreshToken: false` — allemaal bewezen, incl. SW-dood/herstart en extensie-reload. Alarm in prod op ~50 min (spike draaide op 1 min).
4. **RLS-leerpunt:** een admin-account ziet álle `profiles`-rijen — elke profiel-query in de extensie moet `.eq('id', uid)` filteren (geldt straks ook voor de beta-gate-check in F1b).
5. **Beslispunt volgens plan §5.3:** spike = groen; de go voor F1a hangt nu alleen nog aan de beta-cijfers + owner-besluiten (TV-ToS lezen, Web-Store-account, A/B-keuze is de facto A). F1a raakt de web-app → ná launch-week (freeze).

*Wegwerp-extensie: na deze spike verwijderen via `chrome://extensions`. De tijdens de spike in de chat gedeelde `sb_secret`-key moet geroteerd worden in het Supabase-dashboard.*
